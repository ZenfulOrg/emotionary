# Emotionary 1.6.2 — signup and widget follow-up

Build: `2026101501` (app and widget).

Addresses the two October 14/15 reports in [Keila's feedback](https://docs.google.com/document/d/1WUqz_SFDgi7x5jfTSJFWfubc2KVa5iFEyRcGf8S91XQ/edit).

## Email signup

Production Auth logs identify the reported attempt as `user_repeated_signup` with HTTP 200, followed by successful Google sign-in. Supabase intentionally returns an obfuscated user for an already-confirmed account; this response does not send a signup confirmation email. The app previously interpreted every successful response without a session as “email sent.”

The client now recognizes an explicitly empty identities array, both in the raw REST user response and a nested user response. It moves to sign-in with guidance to use the existing password or original Apple/Google provider. The explicit `user_already_exists` error follows the same path. New and unconfirmed accounts retain code verification and resend. No privileged account-lookup endpoint or server auth setting was added.

A fresh, user-authorized Gmail alias signup returned HTTP 200 with an email identity and a confirmation-sent timestamp. The user confirmed inbox receipt on October 15. The supplied eight-digit code verified successfully, password sign-in succeeded, and repeating signup returned HTTP 200 with `identities: []` and no session. The app’s authenticated delete-account endpoint removed the disposable account; a subsequent password sign-in was rejected. No test password or session was saved to disk.

## Widget

The archived extension previously had `CFBundleDisplayName = ExpoWidgetsTarget`. It now uses `Emotionary` in both the native project and the config plugin so regeneration preserves the name. The extension bundle identifier and widget kind remain unchanged, preserving existing installations.

Widget timelines now initialize as soon as local content/user state hydrates, including during onboarding. Previously initialization required completed onboarding despite the widget guide appearing earlier. Empty-props gallery previews now have a complete sample word, definition, color, and links.

These address identified discovery/preview defects; physical-device confirmation is still needed to establish whether they fully resolve Keila's missing-widget report.
